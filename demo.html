End-to-End Encryption Demo

See the message turn into ciphertext before the server could ever read it.

This page simulates a two-person chat using the browser's Web Crypto API. Alice and Bob each get their own identity key pair. Alice creates a shared thread key, wraps it for Bob, encrypts a message locally, and Bob decrypts it locally.

1. Identity Keys Public keys are shareable. Private keys stay local.
2. Thread Key One AES key encrypts the actual chat message.
3. Wrapped Sharing The thread key is protected before it is shared.
Ready to generate identities

The server in this demo is imaginary. It only transports: public keys, wrapped thread keys, and ciphertext.

Flow
Step 1: Generate identity key pairs

Alice and Bob each create an ECDH key pair. Only the public key is meant to leave the device.

Step 2: Create one thread key

Alice creates one AES-GCM key that will encrypt actual message content inside this conversation.

Step 3: Wrap the thread key for Bob

Alice uses her private key and Bob's public key to derive a shared secret, then encrypts the thread key.

Step 4: Encrypt the message locally

Plaintext becomes ciphertext before any transport. This is the core E2EE step.

Step 5: Bob unwraps and decrypts locally

Bob reconstructs the thread key on his side, then turns ciphertext back into readable plaintext.
